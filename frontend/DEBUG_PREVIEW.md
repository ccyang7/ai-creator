# 应用预览功能调试指南

## 重要说明

**ID 类型修复**：所有 appId 和 userId 现在都使用 string 类型，避免 JavaScript number 类型精度丢失问题。

## 问题排查步骤

### 1. 检查应用信息是否正确加载

打开浏览器控制台（F12），查看是否输出以下信息：
- `应用信息加载成功:` - 应该显示完整的应用信息
- `codeGenType:` - 应该显示 `NoCode`、`LowCode` 或 `ProCode`

如果 `codeGenType` 为空或未定义，说明后端接口返回的数据有问题。

### 2. 检查 SSE 对话接口

在对话过程中，控制台应该输出：
- `SSE 连接关闭，aiContent:` - 应该显示 AI 生成的内容
- `appInfo.codeGenType:` - 应该显示代码生成类型
- `appId:` - 应该显示应用 ID

如果 `aiContent` 为空，说明 AI 没有返回任何内容。

### 3. 检查预览 URL

预览功能启用时，控制台应该输出：
- `预览 URL:` - 格式应为 `http://localhost:8200/api/static/{codeGenType}_{appId}/`
- `预览已启用，URL:` - 同上

确保这个 URL 在浏览器中可以访问。

### 4. 检查 iframe 加载

iframe 加载时应该输出：
- `iframe 加载完成` - 表示成功加载
- 如果输出 `iframe 加载失败`，会显示错误提示

### 5. 常见问题

#### 问题 1：codeGenType 为空
**原因**：创建应用时后端没有正确设置 codeGenType
**解决**：检查后端创建应用接口的实现

#### 问题 2：预览 URL 404
**原因**：后端静态资源服务未正确配置
**解决**：确保后端 `/api/static/${codeGenType}_${appId}/` 路径可以访问

#### 问题 3：SSE 连接立即关闭
**原因**：后端 SSE 接口有问题
**解决**：检查后端对话接口的实现

#### 问题 4：跨域问题
**原因**：iframe 加载不同源的 URL
**解决**：确保前后端都配置了 CORS

## 测试流程

1. **创建应用**
   - 在主页输入提示词
   - 点击"开始创建"
   - 观察控制台输出

2. **对话生成**
   - 在对话页面与 AI 交流
   - 观察 AI 回复内容
   - 等待代码生成完成

3. **检查预览**
   - 代码生成完成后，右侧应该自动显示预览
   - 查看控制台是否有错误信息
   - 如果显示"已加载"标签，说明预览成功

4. **部署应用**
   - 点击"部署"按钮
   - 获取部署 URL
   - 点击"访问已部署网站"

## 调试技巧

### 手动测试预览 URL
在浏览器中直接访问：
```
http://localhost:8200/api/static/NoCode_{appId}/
```
将 `{appId}` 替换为实际的应用 ID。

### 检查网络请求
打开浏览器的 Network 面板：
1. 查看 `/api/app/chat/generate/code` 请求
2. 查看 `/api/static/*` 请求
3. 检查响应状态码

### 清除缓存
如果预览不更新：
1. 按 Ctrl+F5 强制刷新
2. 清除浏览器缓存
3. 使用无痕模式测试

## 预期行为

1. 创建应用后，自动跳转到对话页面
2. 发送初始消息后，AI 开始回复
3. AI 回复过程中，消息逐字显示
4. AI 回复完成后，右侧自动显示预览
5. 预览区域显示"已加载"标签
6. 可以点击"刷新"按钮重新加载预览
